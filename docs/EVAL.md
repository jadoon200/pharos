# Evaluation

> The point of PHAROS is not that it *emits* maritime incidents — a few thresholds can do that.
> The point is that the incidents are **measured**: the detectors are scored per threat type, the
> flagship model is held to a cross-region generalization bar, and the honest failure modes (above
> all, the AIS coverage confound) are recorded, not hidden. This document defines the bar and will
> record every result, including the negatives. Numbers fill in as milestones land (see
> `docs/ROADMAP.md`); placeholders are marked `TBD`.

## What we measure

### 1. Per-incident-type detector quality (the ensemble)
Each detector covers a different maritime threat. Scored against a labelled gold set + Global
Fishing Watch event labels as a silver cross-check.

| Detector | Threat | Metric | Result (offline gold set) |
|---|---|---|---|
| gap | dark ship / AIS gap | precision / recall vs injected labels | 1.0 / 1.0 † |
| rendezvous | ship-to-ship transfer | precision / recall vs injected labels | 1.0 / 1.0 † |
| loiter | loitering / zone incursion | precision / recall vs injected labels | 1.0 / 1.0 † |
| spoof | impossible kinematics / identity | precision / recall (deterministic ground truth) | 1.0 / 1.0 |
| anomaly | trajectory deviation | ROC-AUC (anomaly vs normal transits) | 1.0 † |
| **ensemble** | **all types** | **per-type coverage (best detector each)** | **all 5 types covered** |

The live block under **Auto-recorded results** is regenerated by `make eval` (5 seeds). † These
offline numbers are near-perfect *by construction* — the synthetic events are separable — so they
demonstrate the harness, matching, and trap logic, **not** real-world difficulty. Real-magnitude
numbers come from the same detectors on downloaded NOAA AIS + the GFW cross-check (`gfw_check.py`).

### 2. Cross-region generalization (the headline)
Train the pattern-of-life / anomaly model on one waterway, test on another traffic regime; report
the number that *survives* the region change (the maritime analogue of SENTINEL's cross-network
transfer result). The features are heading-invariant and region-agnostic (route *shape*, not
place), which is what makes the transfer possible.

| Metric | Definition | Result (offline gold set) |
|---|---|---|
| Within-region AUC | anomaly AUC on same-region tracks (train Singapore, test Singapore) | 1.0 |
| Cross-region AUC | same model, different region (train Singapore, test US west coast) | 1.0 |

On the synthetic gold set the transfer is complete because the shape features fully normalise
compass heading; the *methodology* — a region-agnostic shape descriptor scored across regions — is
the transferable result. On real AIS the number will be lower and is the honest thing to report.

### 3. The AIS coverage confound (the honest limitation)
An apparent "dark ship" is often a benign receiver-coverage gap, not evasive behaviour. The gap
detector already requires displacement (a gap with ~0 movement is not flagged), the offline eval's
**coverage-gap trap** exercises exactly this (held 5/5 seeds), every incident carries an AIS
reliability grade, and GFW's reception-modelled gap events are the real-world cross-check.

| Metric | Definition | Result |
|---|---|---|
| Coverage-gap trap held | benign anchored-vessel gaps not called dark-ship | 5/5 seeds |
| Gap FP rate vs coverage (real data) | share of "dark" calls attributable to reception gaps | needs NOAA + GFW |
| Reliability calibration (real data) | do low-reliability incidents concentrate the false alarms? | needs NOAA + GFW |

## Recorded negatives

Recorded here as they are found (this is the point, not an afterthought). Additions land as the
real NOAA/GFW validation runs; the offline gold set's known limitation is that it cannot exhibit
the AIS *coverage confound* at real-world scale — the coverage-gap trap probes it in miniature (a
long benign silence with ~0 displacement that the gap detector must not call dark-ship), and the
GFW gap-event cross-check is the real-world measurement.
